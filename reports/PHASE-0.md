## Current contract and security findings

Current entry format is plugin-level JSON. Top-level keys are name, owner, description, version and plugins. Each plugin supplies name, repo, ref, sha, path, skills, description, maintainer, license and hosted_services. There is no machine-readable schema. CATALOG.md and .claude-plugin/marketplace.json are generated; the latter points at local vendored plugin folders with strict:false and explicit skill paths.

“Pinned” means a full source commit is recorded and sync.py downloads its GitHub archive. It copies selected skill folders plus root license files, then writes source identity. It does not verify the named ref against that SHA, calculate the requested tree_sha256, validate signatures or pin live docs/SDK dependencies.

“Checked” means heuristic static checks: duplicate names, size, recognizable license text, frontmatter markers and name/description presence, a scope-boundary word, selected backtick references, some secret/path patterns and hosts. CI re-vendors, checks tracked diff, then checks the reconstructed tree. It neither tests scientific behavior nor verifies biosafety, receipts or deployment status.

“One-line import” describes marketplace registration or a Science import entry. Claude Code still requires plugin installation after marketplace add. The README's Code line is unpinned. Its Science line names v0.1.0, an older index snapshot containing SZL v0.1.2; v0.1.1 points to audited main containing SZL v0.1.3. Registry/marketplace version remains 0.1.0. ## Conflicts and decisions that must stay explicit

C1. Existing vendoring vs pointers-only target.
The entire current architecture copies upstream code. The payload simultaneously says never copy third-party code and preserve existing conventions when they conflict. Phase 0 must preserve the tree and report the conflict; it cannot silently migrate, delete vendored files or resolve policy precedence.

C2. Nine LISTED seeds vs keyed-service exclusion.
szl-typesafe-ai needs the user's TypeSafe key, while the target forbids requires-key skills from being installable. Therefore nine existing seeds cannot all be assumed LISTED under the unchanged rules. Either retain this as non-installable metadata or await a human-approved policy/source change. Do not relabel a keyed API keyless because it is optional.

C3. License vocabulary.
Preserve the requested allowlist exactly pending human clarification. MPL-2.0 is weak copyleft, not permissive; CC-BY-4.0 is for documentation, not an OSI software license. Generic BSD is not a precise SPDX identifier; accepted BSD variants/expressions need definition. Unknown, mixed or unapproved terms must route to review, not auto-pass.

C4. Offline checking vs acquisition.
Fetching a GitHub tarball needs network; checking and executing untrusted tests can be offline only after bounded acquisition. Separate networked cold fetch/cache verification from a network-disabled, credential-free validator/test sandbox. No paid service or provider key is needed to acquire public source. A host's subprocess API or environment variable alone does not provide network isolation.

C5. Proposed CI credentials.
PR #2 supplies the ephemeral GitHub job token to the source-fetch step. It is not a paid scientific-provider key, but it is a credential. Clarify whether “no API keys in CI” permits GitHub's standard short-lived job token for public-source rate limiting; the offline checker should receive none. Do not silently claim the proposed workflow is keyless.

C6. Test policy and finite statuses.
tests=NONE is allowed in the schema, but listing eligibility with NONE is unspecified. Infrastructure errors/timeouts must not become scientific FAIL or PASS without reasons; define BLOCKED semantics separately. UNSIGNED_HONEST describes attestation, not test success. “No keyword matched” is not human biosafety approval. Clinical/dosing approval must be bound to exact source/policy revisions.

C7. Hash definition and trust anchor.
Define exactly what tree_sha256 commits to: selected skill path, relative path encoding/order, raw file bytes, file types/modes, symlink policy, exclusions and required license/NOTICE bytes. A compressed archive hash differs from a canonical extracted-tree hash. A digest in an untrusted manifest can be changed with its content; bind check receipts to a trusted reviewed source commit/checker/policy. No signature establishes scientific truth.

C8. Human-only boundaries.
The target says to open upstream issues for failures, but §9 reserves all maintainer outreach for humans. Produce reviewable failure evidence; humans send it. Biosafety policy text, safety approval, delisting disputes, org membership/governance, and Anthropic contact remain human-only. No issue/comment has been sent.

C9. Skills source is newer and independently owned.
szl-holdings/szl-skills main at 54890f38c4b5abeefb13441e6f3cfd6f80c34769 includes the nine named seeds and the paired-science work merged at 03:18 UTC. It has 49 tracked files; this audit inspected its inventory and relevant contracts, helpers/tests metadata, not all external scientific dependencies. Do not overwrite it or claim its six new science helpers were tested here. The existing governed-decision entrypoint lacks license frontmatter, an explicit seed prerequisite rather than a universal Agent Skills requirement. Proposed P0 skills are future candidates, not checked inventory.
